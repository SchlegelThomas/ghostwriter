Ghostwriter delivery plan

Agent dock QOL

Status: active
Branch: feat/writing-agent-harness (continues harness PR)
Owner: founder + parent agent

Intent

Make the Agent dock feel like a continuous writing conversation — Cursor-inspired QOL (grouping, markdown, sessions/tabs, fork, copy) adapted for Ghostwriter’s chat / Plan / agent modes, propose-only invariants, and manuscript selection. Prefer a soft, flowy rhythm over a debug console.

Out of scope: multi-agent parallel runners; marketplace skills; silent manuscript writes; turning Agent into a second editor; Playwright until founder verifies; server-synced chat history (local persistence first).

Domain / design audit

  • Canonical: manuscript, captures, proposals unchanged. Chat sessions are noncanonical UI state (like agent prefs), not a second story store.
  • Messages: today UI-only; each API turn is one writer message + server-assembled project/selection context. Optional prior-turn snippets may be sent for regenerate/edit coherence without becoming authority.
  • Authority: ADR 0011 / 0013 — propose-only; no client-pasted canon as truth.
  • Living design: Mockups 4.0/5.0 — writing agents / BYOK; harness modes from writing-agent-harness plan. Soft chrome may diverge from harsh ASSISTANT labels.
  • MCP: no new mutation capabilities; dock QOL is UI + existing chat/stream.

Acceptance criteria (epic)

  • A: Assistant replies render markdown (headings, bold/italic, lists, links, inline code); softer turn chrome (no harsh ASSISTANT stamp); copy message action.
  • B: Status + tool traces group into a collapsible “Working” block per turn; collapsed by default when the turn finishes; expandable while/after streaming.
  • C: Multiple chat sessions per project with tabs/history; new chat; rename; persist in localStorage (account+project); resume last session; clear/archive.
  • D: Fork chat from a message into a new session; edit & resend last user message; regenerate assistant turn (same mode/model/effort defaults).
  • E: Stop generation while streaming; retry failed turns; follow-up chips under replies (e.g. open scene / Save to Plans when relevant); selection can deep-link open.
  • Prior harness features (stream, toolkit, Plan→Plans) remain coherent.
  • pnpm verify green; no Playwright until founder verifies.

Tasks (vertical checkpoints)

  1. A — Readability: Lite markdown renderer in packages/ui (no HTML dump); restyle turns; copy control. Vitest for markdown helper.
  2. B — Grouped working: Collapsible working group for statusLabel + toolTraces; streaming-aware expand state.
  3. C — Sessions: workspace-chat-sessions.ts prefs module; App owns session map; tab strip / history menu in dock; persist + quota.
  4. D — Branching: Fork / edit-resend / regenerate wired through App chat send; optional priorTurns on chat/stream for coherence (bounded).
  5. E — Continuity + stop: AbortController wired client→fetch→tool loop; Stop button; retry; follow-up chips + open-scene callback.
  6. Docs: PRODUCT/API note; plan record; WHERE-I-LEFT-OFF.

Tests and verification

  • Vitest: markdown lite; session normalize/persist; working-group collapse helpers; resolve follow-up chips; abort wiring unit where practical.
  • Focused UI/client typecheck; pnpm verify.
  • Manual: stream with tools → grouped Working; markdown reply; new tab / fork / regenerate; Stop mid-stream; scene chip opens Draft.
  • No Playwright until founder verifies complete outcome.

Documentation and ADR impact

Update docs/PRODUCT.md (Agent dock QOL). Light docs/API.md if priorTurns added. No new ADR unless session persistence becomes server-canonical (local-only → no ADR). Living design: Mockups 4.0 / harness plan — additive UI, not a living-design rewrite.

Risks and decisions

  • Accepted: Sessions are local noncanonical UI state; not offline manuscript.
  • Accepted: Lite markdown (subset) over heavy HTML markdown deps for RN-web.
  • Accepted: Fork/edit/regenerate may send bounded prior turns for coherence; server context remains authoritative for project/selection.
  • Risk: localStorage quota — cap messages per session and session count.
  • Risk: Stop must abort provider work; wire signal through SSE + streamWithTools.
