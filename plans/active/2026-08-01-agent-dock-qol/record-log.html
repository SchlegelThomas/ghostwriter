2026-08-01 — Enter bug root cause + one model chip

  • Bug: Enter never sent because react-native-web 0.21.2 TextInput assigns supportedProps.onKeyDown = handleKeyDown, dropping any caller-supplied onKeyDown, and only calls onSubmitEditing for multiline when blurOnSubmit is set. Fix: use the forwarded onKeyPress hook and preventDefault() (which also suppresses RNW’s own Enter path). Helper now ignores IME composition (isComposing / keyCode 229) and native-shaped events, so native keeps newline. Do not set blurOnSubmit — it would blur the composer after each send.
  • Model + effort are one chip (Model · Effort) opening the model menu; rows expose Edit which pins that model’s Effort options in the adjacent pane without dismissing, per Cursor-like nested menus. Row body still selects and closes. Edit is a sibling of the row pressable (not nested) so select-and-close can’t swallow it, and hover is tracked on both so the control stays reachable.
  • pnpm verify green (963 tests).
