Ghostwriter delivery plan

Writing agent harness

Status: active
Branch: feat/writing-agent-harness
Owner: founder + parent agent

Intent

Make Ghostwriter the agentic harness for creative writing: a Cursor-like Agent dock where writers pick a writing mode/agent, choose frontier model + effort, attach book/project/idea context, chat with tools (MCP capabilities), and receive propose-only results they can review and apply. Ghostwriter owns the writing-specific layer (workflows, context receipts, playbooks, toolkit agents); providers supply models under BYOK.

Out of scope for this plan: marketplace / multi-tenant orgs; Anthropic/Google adapters (OpenAI first, multi-provider port already exists); silent canonical writes; replacing Plans Scene Partner flows wholesale in CP1; Playwright until founder verifies.

What already exists

  • Shell: secondary Agent | Properties with docked WorkspaceChatPanel.
  • ADR 0011 platform: BYOK OpenAI, context receipts, runs/proposals, playbooks, MCP grants — used mainly from Plans / Scene Partner.
  • Capability catalog + MCP server; workspace chat today is tool-only (navigator read) and does not call the LLM.
  • Writing jobs in Mockups 4.0/5.0: Scene Partner, Character Coach, Worldkeeper, Sketch Partner (propose-only).
  • Writer-facing Plans (ex–Dreams & Ideas) opens in the center pane; Capture stays modal.

Acceptance criteria (epic)

  • Agent dock composer shows mode and model/effort controls (Cursor-like placement on the input bar).
  • With a valid BYOK key, chat mode answers about the open project using server-assembled context (not tool-echo-only).
  • agent mode can start (or deep-link) a toolkit agent job (at least Scene Partner / cover concept) with receipt confirm when egress spends budget.
  • Chat can invoke MCP/read capabilities and surface tool results in-thread; apply remains human-gated.
  • Plan mode produces outlines/proposals/drafts that land in Plans (center pane).
  • Propose-only and ADR 0011 invariants hold; no silent manuscript writes.
  • Settings still owns key entry; dock shows clear “configure OpenAI” empty state when missing.

Tasks (vertical checkpoints)

  1. CP1 — Composer chrome: Mode picker + model/effort picker on WorkspaceChatPanel (docked). Persist last mode/model/effort per project in localStorage. Empty/disabled states when no BYOK key. No LLM yet — UI + prefs only, wire into send payload stubs.
  2. CP2 — chat mode completion: Upgrade POST /api/workspace/chat to receipt-backed chat: server assembles project/selection context, calls OpenAI via existing packages/ai + BYOK runtime, streams or returns assistant text. Tool-only fallback when key missing. Vitest + hermetic fake provider.
  3. CP3 — Tools in the loop: Allow chat/agent to call a bounded set of read capabilities (project.navigator.read, budgeted scene.workspace.read for whole-book access via iterative reads, capture.list) as tools; show tool-step traces in chat. No egress-confirm modal for this light path. Still propose-only for mutations. No vector DB in this plan — defer embeddings until budgeted scene reads are insufficient at novel scale.
  4. CP4 — Toolkit agents (agent mode): Mode → all toolkit agents in v1: Scene Partner, Cover, Character Coach, Worldkeeper, Sketch Partner. Starting a job uses existing run/proposal or Scene Partner turn APIs; dock shows status + link to review/apply (Plans or inline proposal card). Deep-link; do not delete Plans Partner.
  5. CP5 — Plan mode + docs: Plan-mode outlines persist as a typed agent proposal (new workflow, e.g. plan-mode.outline) that lands in center-pane Plans; PRODUCT/ARCHITECTURE/ADR note for harness modes; WHERE-I-LEFT-OFF.
  6. CP6 — Streaming chat UX: SSE on workspace chat so the dock shows live status / tool steps / typing while the model works (no silent wait). Keep JSON route; add /stream.

Tests and verification

Risks and decisions

  • Accepted modes: chat / Plan / agent (not Ask/Partner). chat = Q&A, research, draft ideas; Plan = outlines/proposals/drafts that land in Plans; agent = toolkit writing jobs.
  • Accepted: Plans view always opens in the center pane (wide and narrow); primary side stays Explorer or Characters.
  • Effort: Map to provider knobs (e.g. reasoning effort / max tokens / “fast vs thorough”) — exact OpenAI fields TBD in CP2; UI labels Fast / Standard / High first.
  • Multi-provider: Catalog may list OpenAI models only in v1; Anthropic later behind same port.
  • Cost: Every chat turn spends BYOK budget — keep receipt/confirm for expensive agent jobs; lighter chat may skip modal and show inline destination chip (decision in CP2).
  • Accepted (CP3): No egress-confirm modal for chat/tool-read loops. Whole-book access = navigator + budgeted per-scene workspace reads (not one-shot manuscript dump). Vector/RAG deferred; no manuscript MCP search today.
  • Accepted (CP4): Ship all five toolkit agents from agent mode (Scene Partner, Cover, Character Coach, Worldkeeper, Sketch Partner).
  • Accepted (CP5): Plan → Plans via typed agent proposal workflow (not Capture-only).
  • Dual chat: Keep Scene Partner in Plans vs fold into dock — CP4 should deep-link, not delete Plans Partner in v1.
