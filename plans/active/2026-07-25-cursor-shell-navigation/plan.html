Ghostwriter delivery plan

Cursor-like workspace shell navigation

Status: active
Branch: feat/capture-to-story-agents (shared; shell chrome only)
Owner: founder + parent agent

Intent

Redesign project workspace chrome to work like Cursor: thin activity bar, resizable primary explorer, editor center, and a resizable secondary side for Agent (Chat/MCP) with Properties. Every writer surface must still be reachable without breaking Capture, Dreams, Reader, or propose-only agent rules.

Out of scope: Reader full-screen redesign; production MCP protocol changes; rewriting Canvas board internals; Playwright until founder verifies.

Page-by-page review (must keep working)

  • Project library / Account gate — outside shell; unchanged.
  • Draft — editor center; Properties = Context Dock tabs.
  • Canvas / Split — editor center; secondary may collapse in map-dense.
  • Reader — stays full-screen escape (not forced into 3-pane).
  • Dreams & Ideas — migrate from center takeover → primary-side view or editor tab (checkpoint 3).
  • Idea Capture — keep modal overlay.
  • Settings — keep modal; gear on activity bar.
  • Characters — primary-side view preferred over center launchpad swap.
  • History — later bottom panel; until then rail/overlay remains.
  • Scene Partner — stays inside Dreams flow; workspace Agent panel is MCP/workspace chat.
  • Jump / Command — palettes remain.

Acceptance criteria

  • Wide layout reads as activity bar | primary | editor | secondary.
  • Primary and secondary widths resize with drag; widths persist per project (localStorage).
  • Agent panel mounts live WorkspaceChatPanel (Chat/MCP); Properties keeps inspector/Context Dock.
  • Manuscript explorer uses clearer folder/file-style kind icons and remains scrollable/searchable.
  • Draft, Canvas, Split, Reader, Capture modal, Settings modal, Dreams still reachable.
  • Narrow mode keeps usable tab/rail fallback.

Tasks (vertical checkpoints)

  1. CP1 — Secondary Agent panel + resize persistence: tabbed Agent | Properties; mount WorkspaceChatPanel; resize + persist secondary width; Chat rail opens Agent tab.
  2. CP2 — Activity bar + explorer icons: Cursor-like activity grouping; file-explorer style tree glyphs; persist primary width.
  3. CP3 — Dreams / Characters as primary views: stop Inbox center takeover; explorer host switches views.
  4. CP4 — Title Page home: remove Project Structure launchpad; project selection opens a Title Page (series title, book cover shelf, design desk). Persist light BookCover concept/notes; AI proposes cover concepts (BYOK), images preview ephemerally until hosted media exists. Characters stay in the primary Characters view.
  5. CP4c — Cover options async + Save details: Fix Title Page Save details feedback (silent no-op when unchanged; draft reset on navigator re-render). Move cover image gen to async jobs that produce ~3 options; History toast when ready; studio review strip to pick / iterate / apply.
  6. CP5 — History bottom (optional) + narrow polish + docs: PRODUCT/ARCHITECTURE notes; WHERE-I-LEFT-OFF.

Risks and decisions

  • Accepted: Agent secondary side uses existing workspace MCP chat; Scene Partner remains Dreams-scoped.
  • Accepted: Reader stays full-screen.
  • Accepted CP3: Wide Plans (ex–Dreams)/Characters host in primary side historically; Plans later accepted as always-center. Characters still primary browse until Cast studio plan is accepted. Narrow Plans still takes center.
  • Dual chat UIs (Scene Partner vs workspace Agent) must stay clearly labeled.
  • Accepted CP4: Project home = Title Page, not structure browse. Cover imageUrl is optional HTTP(S) only; AI-generated bitmaps preview in-session and do not write giant data URIs into Lakebase. Concept/notes persist on the book.
  • Accepted CP4b: BYOK cover image preview (data URI) → Apply puts PNG in private R2 (same Capture bucket) under projects/{projectId}/books/{bookId}/cover.png; Lakebase stores a stable https://ghostwriter.cover/... locator; Title Page resolves a short-lived signed GET (or hermetic data URI) for display.
  • Accepted CP4c: Cover generation is async (in-process job store for v1; not a durable queue). Default 3 portrait options; writer can leave the studio and get a History acknowledgement when ready. Iterate = new job from selected option + refinement notes. Lakebase still stores only the applied locator.
