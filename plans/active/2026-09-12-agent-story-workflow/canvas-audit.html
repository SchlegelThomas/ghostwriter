Canvas: make the foundation dependable

Existing tools are substantial. The missing pieces are reliable scope, navigation, history, responsive behavior and narrative meaning.

Review scope

Review of existing Canvas features before approving the story-agent epic. Parent performed a fresh browser walkthrough; two read-only research agents independently examined UI/design and domain/storage/API/MCP. Compared Mockups 2.0–5.0 ownership, accepted ADR0007/0009 boundaries, Canvas3 plan/log, current code and tests. No implementation or living-design edits.

Browser: Codex in-app surface, localhost:8081, isolated PGlite demo with 21 scenes/7 books; wide 1600×1000, narrow 390×844. Created one labeled audit note, placed one existing scene, added one thread link and exercised Undo/geometry. No manuscript prose was edited and no provider was called. These are temporary demo changes, not production data.

Verdict: preserve the tools and canonical-ID architecture, but put two Canvas foundation checkpoints before the shared narrative spine. Separate browser-reproduced defects, code-confirmed gaps and unverified behavior. Passing helper tests do not establish a usable complete workflow.

Scope boundaries and durable decisions

Scope membership must become explicit rather than a side effect of a thread edge. Selection for inspection must be independent from the scene currently being edited. Consecutive Undo requires a documented history contract, and spatial coordinates must agree across pointer, inspector and ordered views. These extend or clarify ADR0007/0009 and belong in proposed ADR0018 before coding.

Keep region grouping, image-reference metadata, link gestures and all existing command states working. Defer new general-purpose whiteboard features: multi-select/group transforms, automatic layout, region-as-navigation hierarchy, binary image workflows, multiplayer cursors and implicit manuscript reordering. No redesign of the entire shell is required. Existing accepted founder changes (no peek, no success-toast flood, compact toolbar) take precedence over earlier mockup details.

Fresh browser walkthrough

Each screenshot was captured in this run, saved, reopened and inspected. Screenshots document visible states; behavioral claims also use the intervening accessibility-state observations. A scrolled geometry capture was rejected and excluded.

1. Open an existing story on Canvas

Needs improvement. The demo contains 21 scenes, yet Canvas starts with “An open board.” The collapsed spine is the only immediate hint of existing scenes. This is an empty spatial board, not an empty story. Provide Show this chapter/story and explicit placement of existing scenes. Current shell preferences retain a large Explorer and Agent; assess remaining board space rather than assuming old collapsed-default mockups are authoritative.

2. Expand the reading spine

Useful but difficult to scan. Three display sizes expose canonical scene order and Not placed status. The expanded strip is horizontal, chapter labels are generic, and chapter scope later still reports all 21 scenes. Keep compact options while adding This chapter / Whole story scope and recognizable destinations.

3. Open an unplaced scene in Draft

Works with indirect entry. Spine selection selects the real manuscript scene; Open selected scene reaches its actual prose. Return to Canvas preserved the selection but reset spine presentation. Story purpose and downstream context are not yet present beside prose.

4. Create and rename a note inside a chapter

Confirmed defect. Note tool → board click → Saved → rename to Canvas audit note succeeds. Inspector shows the new object while the chapter still says An open board. Returning to project scope reveals it. Scope is inferred from connected scene cards, so new unlinked objects disappear. Creating in a scope must establish deliberate visibility without inventing a narrative relationship.

5. Place an existing scene

Core handoff works; discovery needs improvement. Scene dialog offers Place selected Draft scene and explicit book/chapter-or-Unassigned destinations for new scenes. Placing Morning on Privet Drive adds a card without increasing the 21-scene manuscript. Existing-scene placement is buried inside Create a scene; the all-books destination list and zero-based order hint are cumbersome. New scene creation itself was inspected but not submitted in this run.

6. Connect scene and note

Works for typed spatial links. Inspector creates an acknowledged confirmed thread link; the relation is listed and rendered. Once linked to the chapter scene, the note becomes visible in that chapter. This accidental visibility coupling must be separated from narrative meaning. “Create provisional thread fixture” leaks development language into the writer workflow.

7. Undo twice

Confirmed defect. First Undo removes the thread link; second Undo restores it. The UI reports both as Canvas action undone. Core chooses the immediately prior snapshot, including the previous Undo snapshot, so it toggles between states. Require predictable traversal through writer actions and a distinct restore operation.

8. Inspect lenses and history

Partial; semantics need clarification. Relationships displays linked objects. Continuity hides these ordinary objects and produces the same An open board message, without explaining the filter. Plan → Draft restores ordinary objects. Review opens Recent actions & snapshots; it is not the proposed narrative review workflow. History eventually lists snapshots (observed after this capture); loading, empty and failure must be explicit.

9. Use the ordered view

Useful alternative; incomplete context. Cards have named controls, active/confirmed states and descriptions. The list contains the placed scene and connected note, not all chapter scenes, while the footer is whole-story. Position/size shown in this view use global object values even after scoped drag, so accessibility geometry can disagree with the spatial card.

10. Inspect Canvas at 390 × 844

Confirmed layout defect. The ordered-view heading breaks into vertical text; the tool area is not usefully visible in the captured layout. The two object rows remain legible. Phone reflow needs a real layout pass, not only switching spatial rendering off.

11. Select an item on narrow Canvas

Needs repair. Selection opens an inspector at a scrolled middle section above the object list. The visible viewport lacks a clear inspector title/close action and begins with order hints rather than scene context. Provide a focus-managed sheet/route with a reachable back action and correctly restored list position.

12. Search for an unplaced scene

Confirmed functional gap. Searching The first letter yields no result or no-results explanation even though that scene is visible in Explorer. Canvas search currently searches board objects, not all manuscript scenes. Code also shows archived/dismissed object inclusion and no scope/lens reveal. The / shortcut did not focus search in a separate keyboard check; its exact aria-label selector is mismatched in code.

13. Select a different spine entry in Split

Current coupling verified. With Morning on Privet Drive open in Draft, selecting The first letter in the spine replaces the active document. An explicit navigation action can do this, but a stable distinction between inspect and open must be designed across spine and cards.

14. Inspect a Canvas card in Split

Conflicts with planned writing continuity. With The first letter open, selecting the Morning on Privet Drive Canvas list card also replaces Draft with Morning on Privet Drive, without choosing Open Draft. The inspector then dominates the Canvas pane. Separate inspected object from active writing scene; preserve caret/lease until explicit Open.

15. Move a linked card in chapter scope

Basic drag works; geometry parity missing. Dragging the scene card moves it and the link endpoint follows in the resulting screenshot; save acknowledges. Inspector/ordered view still report global coordinates. Inspector Wider changes global width, whereas scoped spatial geometry takes priority. Pointer north/west resize additionally submits move and resize separately in code, risking a same-version conflict. All gesture/control paths need one scope-correct commit.

Verification and limits

Existing core/scope/UI helper tests: six files, 89 tests passed (canvas-services, canvas-scope-placements, canvas-model, canvas-interaction, canvas-chrome, canvas-drill). Log: /tmp/ghostwriter-canvas-audit-tests.log. Postgres Canvas repository: one file, eight tests passed (97 focused tests total). Storage log: /tmp/ghostwriter-canvas-storage-audit-tests.log. Earlier full pnpm verify passed 1107 tests; that is a prior baseline, not a new audit run.

Not exercised end-to-end in this audit: live-model checks, simultaneous stale-version writers, all eight pointer resize handles, touch pinch on physical devices, full screen-reader navigation, all archive/restore and provisional paths, region membership lifecycle, new scene submission, image metadata creation, full-board snapshot restore and large-project interactive performance. These are explicit acceptance obligations, not claims of working behavior. Existing tests/code cover parts of them. No Playwright run or authoring; no infrastructure or production change.

Accessibility findings concern observed reflow/focus and code-level keyboard behavior; no compliance claim. Performance issues are measured-work requirements derived from storage implementation, not measured latency regressions.
