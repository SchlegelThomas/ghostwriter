Founder decisions (accepted 2026-08-01)

  1. Egress: Default is local guide + explicit Start (A). Writers can also enable auto suggestions with a toggleable Ghostwriter mark at the top of the Agent pane (ambient cheap-coach after save/idle). Toggle off = back to Start-only. Bigger models still require a separate confirm.
  2. Landing: Entity Drafts + dock chips — not a new global Suggestions inbox.
  3. First vertical checkpoint: Scene prose save + idle.
  4. Entity detection: Cheap-coach structured extraction (not local proper-noun heuristics as the primary path). Extraction compares scene prose against the project cast/SK list the coach is given — no vector DB required for this epic (see Risks).

Intent

After meaningful writer work, Ghostwriter should quietly suggest the next useful move — create missing story knowledge, sharpen craft, or engage the right catalog agent — without becoming a nagging second inbox or silently spending BYOK budget.

Today, catalog agents (Idea Midwife, Pacing Doctor, …) and entity Drafts only appear after the writer manually starts a run. Capture’s designed quiet invite (“Help find its place?”) is the only living-design proactive pattern, and it must stay local until the writer confirms egress (ADR 0011). This plan generalizes that pattern across the workspace and adds an optional cheap coach tier (Haiku / Flash / GPT-4.1 mini class) that can observe a change and propose next actions — escalating to a stronger model only when the coach asks and the writer opts in.

Out of scope for v1 of this epic: autonomous multi-agent swarms; silent manuscript or story-knowledge writes; scheduled background agents while the writer is away; marketplace skills; collaboration suggestion queues; import-pipeline audits; Playwright until founder verifies the complete outcome.

Product model

Three tiers

Tier When Cost Examples
Local guide After acknowledged state change + idle Zero provider spend Quiet invite chips; Quick Build “add scene”; “link cast to scene”; dock nudge naming one catalog job
Cheap coach Writer starts (or ambient opt-in) with receipt Haiku / Flash / 4.1-mini class, tight caps New-character candidates; “next craft question”; which stage agent fits; thin-premise Midwife prompt
Escalate Coach proposal asks; writer confirms bigger model + scope Sonnet / 4.1 / Pro class Scene Partner integrate; Continuity across many scenes; Pitch / Query; Developmental letter

Invariants

  • Propose ≠ apply. Suggestions open workflows or create ADR 0011/0014 proposals; never mute canon.
  • No spend on keystroke or while Saving; wait for acknowledged save + idle; never steal caret when an agent finishes.
  • Dismissible without nag; durable dismiss per invitation kind where Capture already does.
  • Entity-attached preferred (scene / Cast / Title Page / project Drafts) over a second inbox.
  • Selection refusals stay honest when context is missing.
  • Cheap coach default model from curated catalog (e.g. claude-haiku-4-5, gemini-2.5-flash, GPT mini-class) — writer-overridable; never credentials in prompts.
  • Auto-suggestions toggle in the Agent pane header (Ghostwriter mark): off by default; when on, ambient cheap coach may run after acknowledged save + idle with receipt + hard caps; when off, only local chips + Start. Persist per writer/workspace prefs (same family as dock mode/model prefs).

Domain / design audit (pre-code)

  • Canonical objects: reuse AgentProposal + primaryTarget (ADR 0014) for coach outputs that need Acknowledge/Reject; local chips may be ephemeral UI state with durable dismiss keys — decide per checkpoint whether a proposal row is required.
  • New domain candidate: next-action-v1 (or extend catalog-memo-v1) typed payload: trigger event, suggestion kinds (create-story-knowledge, run-catalog-agent, open-surface, escalate-model), evidence quotes, confidence, recommended model tier.
  • Triggers: today all catalog/Capture runs are manual HTTP. Need a post-change invitation path that never calls providers until confirm (or ambient opt-in). Do not piggyback on prose autosave version domain.
  • Entity detection: none in core today. Accepted: cheap coach structured extraction with cast/SK roster in the prompt context. Vector/embedding retrieval deferred (not required to compare one scene to a roster).
  • Authority: ADR 0011 / 0013 / 0014 — model never applies; receipts before egress; MCP remains read + propose.
  • Living design: Mockups 5.0 quiet invite; Mockups 4.0 job-bound agents / Scene Partner “Next move”; Mockups 2.0 ack toasts with safe next action + Quick Build. Preserve user-authored design files; additive UX only with founder direction.
  • Conflicts: founder Capture note rejected Scene Partner interstitial — Partner opens chat immediately. Quiet invite remains Capture→integration and (proposed) generalized local guide, not a second interstitial for every dock open.

Acceptance criteria

  • Plan accepted with founder decisions on egress posture, landing surface, first CP, and entity-detection approach.
  • Each vertical checkpoint ships a writer-visible next-action path with clear refusal / dismiss states and zero silent canon mutation.
  • Local guide invitations never call a provider.
  • Cheap coach runs use a Haiku/Flash/mini-class default, hard caps, context receipt, and land as entity Drafts or dock chips per decision — never auto-apply.
  • Escalate path prompts the writer to engage a stronger model on an explicit scope; no automatic upgrade.
  • Matrix surfaces above are either implemented, explicitly deferred with reason, or marked non-goals for this epic.
  • Docs/ADR updated; pnpm verify green; founder browser-verifies before any Playwright.

Risks and decisions

  • ADR 0011: quiet invite stays free; ambient spend only when the writer has toggled auto suggestions on (explicit opt-in). ADR will document that the toggle is the confirmation surface for cheap-tier egress posture.
  • Nag risk: too many chips train dismiss-all. Cap concurrent invitations; prefer one high-signal suggestion.
  • False-positive characters: extraction will invent names; require writer confirm before storyKnowledge.create.
  • Cost surprise: even Haiku on large scenes needs truncation + caps + clear receipt; ambient needs debounce/rate limit.
  • Vector DB: deferred. Roster-in-prompt is enough for “new character in this scene?” Embeddings become useful later for whole-book Continuity / semantic retrieval — separate plan, not a blocker here.
  • Version domains: invitations must not share a coarse version with prose autosave / Canvas gestures.
  • Prior epic debt: production migrate owner block and founder verify of catalog Drafts remain separate; this epic does not unblock Lakebase ownership.
