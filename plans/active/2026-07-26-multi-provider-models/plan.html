Ghostwriter delivery plan · Agents / BYOK

Multi-provider models & available catalog

Let writers bring keys for many model labs, see only the models they can actually use in Settings and the Agent dock, and keep Ghostwriter’s propose-only harness provider-neutral — without making a Python gateway the product control plane.

Status: complete — shipping on feat/multi-provider-models

Owner: founder + parent agent

Living designs: Mockups 4.0 · Mockups 5.0

Intent

Today Ghostwriter is OpenAI-BYOK-only: one encrypted credential slot, Settings that only accept an OpenAI key, and an Agent dock model picker hard-coded to Ghostwriter aliases (gpt-5.6-luna|terra|sol) passed verbatim upstream. Writers who already pay Anthropic, Google, Groq, xAI, Mistral, DeepSeek, or an aggregator cannot use those models in the harness.

This plan expands the credential + catalog layer so Settings can store multiple provider keys, the Agent panel lists only models the account can reach, and packages/ai gains first-class adapters (or OpenAI-compatible bridges) for a broad provider set — while preserving ADR 0011 (encrypted BYOK, decrypt only in the backend adapter, propose-only apply, server-assembled receipts, hermetic fake in CI).

Explicitly out of scope: ChatGPT/Claude browser OAuth token reuse; marketplace / org billing; replacing the writing-agent harness CP3 tool loop (parallel plan); making LiteLLM or OpenRouter the sole credential home; local Ollama/desktop-only providers in v1; Playwright until founder verifies the complete outcome.

Research summary (gateway options)

Deep research compared open-source and hosted gateways against Ghostwriter’s real constraints: TypeScript/Node on Fly, per-writer encrypted BYOK, Settings-driven “available models,” and an existing provider-neutral port in packages/ai.

Recommended architecture (proposed D0): extend Ghostwriter’s own registry on top of packages/ai, implement adapters with Vercel AI SDK provider packages (and @ai-sdk/openai-compatible for long-tail), call providers directly with per-request decrypted BYOK. Optionally add OpenRouter as one named provider for long-tail models. Do not self-host LiteLLM as the v1 control plane; revisit only if we need a shared OpenAI-compatible org gateway for non-UI clients.

Settings / Agent panel
  → Ghostwriter model registry (curated catalog ∩ account entitlements)
  → packages/ai ports (structured + future stream/tools)
  → @ai-sdk/* adapters with per-request BYOK
  → [optional] OpenRouter | other OpenAI-compatible as named providers

Product thesis and authority

  • Providers are interchangeable backends. Ghostwriter owns workflows, receipts, playbooks, propose-only apply, and the available-model catalog UX.
  • BYOK stays first-class. Writer keys encrypt under existing Fly KEKs; plaintext decrypts only in the backend adapter immediately before an authorized call (ADR 0011).
  • Available = curated ∩ reachable. Settings and Agent dock never dump raw provider /models noise. Ghostwriter ships a pinned catalog with capability flags; UI shows models only for providers with a valid key (and optional discovery refresh).
  • No silent authority. Multi-provider does not weaken propose-only, receipt confirm for egress, or MCP propose-only grants.
  • Gateway is optional infrastructure, not product policy. LiteLLM/OpenRouter must not own allowlists, playbooks, or context assembly.

Acceptance criteria

  1. Settings AI setup lets a writer add/validate/remove keys for multiple providers (not only OpenAI), with masked hints and validation state per provider.
  2. A server endpoint returns the writer’s available model catalog: curated entries filtered to providers with configured + valid credentials (and capability flags for chat / tools / structured / image).
  3. Agent dock model picker lists only available models; empty/disabled states point to Settings when none are configured; last preference falls back safely if a key is removed.
  4. Chat / agent runs / Scene Partner use the selected provider+model via the shared runtime; receipts and runs record real provider + model ids (not OpenAI-only types).
  5. At least the accepted v1 provider set completes structured completion through hermetic fake in CI and live adapters behind BYOK (see D1).
  6. Credential storage supports one encrypted envelope per (account, provider) (schema migration from today’s account_id PK).
  7. Kill switch, KEK custody, and “never return plaintext / never log keys” invariants hold for every new provider.
  8. Docs: PRODUCT / ARCHITECTURE / API / OPERATIONS + ADR amendment (or ADR 0012) describe multi-provider registry and gateway decision.
  9. Focused Vitest + pnpm verify; browser walkthrough recorded; Playwright deferred until founder verifies.

Domain and design audit

Current state (authoritative code)

  • packages/ai: provider-neutral StructuredCompletionProvider + one live OpenAI Responses/Images adapter + fake; no streaming/tools yet; no Anthropic/Google/OpenRouter.
  • provider_credentials: PK = account_id only — one credential row per account.
  • Types: AgentProviderId = "openai"; AgentModelId = gpt-5.6-luna|terra|sol; egress openai-responses.
  • UI: AiSetupPanel / Settings OpenAI-only; workspace-agent-prefs.ts hard-coded three aliases; WorkspaceChatPanel chips.
  • Runtime: agent-provider-runtime.ts always createOpenAiProvider after decrypt.

Canonical objects to extend

  • Provider credential envelope — per account+provider; existing AES-GCM + AAD pattern.
  • Model catalog entry — Ghostwriter id, provider id, upstream model id, labels, tier/effort map, capability flags, optional image model binding.
  • Available catalog view — noncanonical projection for Settings + dock (not a second store of truth).
  • Context receipt / run / proposal — widen provider + model fields; keep receipt hash rules.

Concurrency / persistence

  • Credential mutations are account-scoped with version/precondition (existing pattern generalized to provider id).
  • Migration: move existing OpenAI rows to composite identity (account_id, provider); no data loss.
  • Agent prefs in localStorage must tolerate model ids disappearing when a key is deleted.

Design map

  • Settings: multi-provider AI setup — provider cards/list, key entry, validate, remove; progressive (skip until agent help).
  • Agent dock: model picker grouped by provider (or flat with provider badge); effort chips remain Fast/Standard/High mapped per-provider.
  • Living design: Mockups 5.0 owns BYOK / progressive setup; Mockups 4.0 owns writing-agent chrome. Preserve files; additive Settings/dock language only if founder asks.
  • Authority on conflict: ADR 0011 + this plan beat mockup flourishes that imply ChatGPT/Claude login reuse.

Binding map

  • Core: multi-provider credential services; model registry; available-catalog query; widen receipt/run types.
  • Storage: migration for provider_credentials PK; repository methods by provider.
  • AI: registry + adapters (AI SDK under the port); keep fake provider.
  • API: /api/me/providers (list/status), /api/me/providers/:id CRUD/validate, /api/me/available-models; deprecate OpenAI-only paths with compatibility shims.
  • UI: Settings + Agent dock + prefs; client API helpers.
  • Capabilities/MCP: same runtime; no credential disclosure via MCP.

Risks and decisions

  • D0 — Control plane (accepted 2026-07-26): Use the open-source Vercel AI SDK npm packages (ai, @ai-sdk/openai, @ai-sdk/anthropic, …) inside our Fly Node backend. This is not “host on Vercel,” and not Vercel’s hosted AI Gateway. Keys stay in Ghostwriter KEK custody; we call Anthropic/OpenAI/etc. directly. LiteLLM stays off the default path.
  • D1 — v1 provider set (accepted 2026-07-26):
    • Wave A: OpenAI, Anthropic, Google Gemini.
    • Wave B (same epic): Groq, xAI, Mistral, DeepSeek + optional OpenRouter.
    • Defer: Azure / Bedrock / Vertex SA complexity; Ollama/local until desktop.
  • D2 — Catalog identity (accepted 2026-07-26): Real provider model ids in the picker (e.g. claude-sonnet-4-5, gpt-4.1, gemini-2.5-pro) — retire Luna/Terra/Sol as the stored model identity. Effort remains Fast/Standard/High posture mapped per provider.
  • D3 — Agent gating (accepted 2026-07-26): Models without reliable tool/structured support are chat-only (or hidden from agent mode) via catalog flags.
  • D4 — Sequencing vs harness (accepted 2026-07-26): Multi-provider first; harness CP3 tools come after this epic’s runtime is in place.
  • D5 — Images (accepted revised 2026-07-26): Image-capable models are selectable too (catalog flag supportsImage). Cover/character visual jobs use the writer’s chosen image model when that provider key is valid; disable image agents only when no image-capable model is available.
  • D6 — LiteLLM (accepted ignore 2026-07-26): No LiteLLM work in this epic.
  • Risk: Provider API surface variance (tools, JSON schema, reasoning effort, image APIs) — catalog flags + adapter tests.
  • Risk: AI SDK major version churn — pin versions; Ghostwriter ports stay stable.
  • Risk: OpenRouter fee/privacy hop — label clearly; never route direct-provider keys through OpenRouter unless the writer configured OpenRouter.
